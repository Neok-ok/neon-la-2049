Memory rules

The graphics tier changes how good the picture looks. The memory budget decides how much of the city stays loaded. Ultra on a phone stays selectable and keeps the street in front of the camera. The horizon is what shrinks.

Source of truth for other passes. Markdown twin: MEMORY-RULES.md.

Create and unload

Every texture, geometry, render target, and material goes through resources in src/core/memory.

import { resources } from '../core/memory';

const geo = resources.geometry(() => new BufferGeometry(), {
  label: 'balcony', owner: 'towers', evictable: true,
});

const pole = resources.sharedGeometry('lamp-pole', () => buildPole());
mesh.userData.sharedGeometry = true; // chunk unload must not dispose this

const tex = resources.texture(() => new CanvasTexture(canvas), {
  label: 'signs', owner: 'signs',
});
resources.markStreamed(tex); // pressure can drop high mips

const mat = resources.material('neon-sign', () => new MeshBasicNodeMaterial());
const rt = resources.target(() => new RenderTarget(w, h), {
  label: 'reflect', owner: 'water',
});

resources.retain(geo);
resources.release(geo); // the last holder calls dispose()

retain and release are the reference count. Shared geometry is never disposed by release. Chunk unload calls release, then dispose only if the resource was never tracked.

main.ts installs a constructor hook before the city builds. A bare new BufferGeometry, texture, render target, or material is still counted. ?memguard=1 throws instead. npm run memory:check fails if a memory-owned file constructs a GPU resource without resources.

About 46% is the JS heap and 40% is GPU. Of the GPU share, about 62% is geometry, 18% textures, 20% render targets. A max texture size of 2048 or less caps textures at 32 MB.

Force a class with ?budget=android, ?budget=ios, ?budget=desktop, or a number of megabytes (?budget=720). ?mem=1 shows the overlay. It is not part of the picture.

What stays loaded

The streamer keeps the tier’s distances when the estimate fits the geometry budget. The estimate is a disc of street chunks at 1.6 MB, mid chunks at 0.9 MB, and 2 km far cells at 1.2 MB.

When it does not fit, the horizon shrinks first, then the mid ring, then the street radius, which stops at 420 m on high and ultra, 280 m on medium, and 200 m on low. Screen-space error can refuse a finer level. Thresholds are 14, 8, 5, and 3.5 pixels. A level that is already showing needs an 18% change, and only one step happens per update, so the skyline does not flicker.

Worker results wait in a queue of at most 16. Only the 12 nearest are kept. Cells past the geometry cap are dropped, farthest first. After about 90 frames under 70% of the cap, the horizon grows back.

While the budget is tight, up to 48 missing 2 km cells draw a few impostor blocks on the shared city material. They leave when the real mesh arrives. A desktop budget that already fits does not show them.

Textures, instances, materials

Window rooms and the sign atlas ship as KTX2. On a phone that can decode a compressed format, the game waits for those files and does not also keep the uncompressed canvas. Software GPUs stay on the procedural atlas.

Under pressure, and on a tight budget when the camera is high, high mips drop: one mip above 280 m, two above 900 m. Standing on the street keeps the full chain. Desktop at rest keeps it at any height.

One material per surface, via resources.material(key, …). Repeated parts (signs, lamps, people, props) share a geometry and draw instanced. A clone that owns its own instance buffers must clear userData.sharedGeometry or unload will skip it and leak those buffers.

Before the tab is killed

The governor watches JS heap and GPU counters. Crossing 82% for 1.5 seconds steps up one level. Staying under 62% for 3 seconds steps back one level. A short spike does nothing.

LevelWhat gives
1Horizon ×0.72, coarser screen-space error
2One mip dropped, horizon ×0.55, wet reflector off
3Resolution ×0.75, two mips dropped, horizon ×0.42

Interiors and towers

An interior is built when the camera comes within its stream radius and disposed when the camera leaves. While the player is occluded inside, the exterior chunks are disposed too. Leaving rebuilds the street.

A landmark keeps the showing level of detail and one neighbour on the GPU. The other level’s buffers are released and uploaded again on the way back. The CPU copy stays so the tower is not rebuilt.

Do not

  • Allocate a large city-wide buffer at the ultra count on every phone. A shorter draw range does not free it.
  • Build a material or a geometry per window, balcony, person, or lamp.
  • Upload a canvas atlas and a KTX2 atlas for the same surface.
  • Push the far distance on a phone out to the desktop ultra radius.
  • Dispose a mesh marked userData.sharedGeometry.

Check

npm run memory:check

The route profiler is node tools/memory/profile.mjs. It emulates a phone, records heap and GPU counters, and walks an opening, a walk, a spinner flight, an interior, and photo mode. Live reads: window.__nla.memory(), __nla.budget(), __nla.pressure().
